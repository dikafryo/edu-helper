# 로그인 후 나이스 복무 자동화 구조 분석

2026-11-02. 설치된 쌤패스 0.16.3의 background.js, neis-request.js, sites.js를 읽어 확인. 사용자 저장 비밀번호·루틴은 조회하지 않았고 실제 신청·상신은 실행하지 않았다.

## 이미 로그인된 경우

1. findNeisMainTab: 모든 Chrome 탭에서 neis.go.kr 하위 도메인과 /jsp/main.jsp 경로를 찾는다. 활성 탭을 우선한다. 부산 pen.neis.go.kr도 조건에 포함된다.
2. neisReadyTab: 탭 로딩 완료뿐 아니라 MAIN world의 cpr.core.Platform과 나이스 메뉴 DOM을 검사한다. URL만으로 로그인 완료라고 판단하지 않는다.
3. startRoute: PIN 해제와 루틴 유효성을 검사한 뒤 준비된 나이스가 있으면 포털 로그인 흐름 전체를 생략한다.
4. runRoute: 해당 나이스 탭을 앞으로 가져온 뒤 종류별 화면 식별자와 날짜·시간·사유·개인결재선 이름을 requestInPage로 전달한다.

## 신청부터 결재선까지

- 복무 종류에 맞춰 개인초과근무관리 / 개인근무상황관리 / 개인출장관리 메뉴를 연다.
- 신청 버튼을 누르고 신청 화면과 데이터 행이 준비될 때까지 기다린다.
- 일반 HTML input 대신 eXbuilder 앱 ID와 컨트롤 ID로 값을 설정한다. 필요한 콤보 이벤트도 발생시킨다.
- 날짜·시간·사유·계산된 일수/시간 또는 데이터셋 값을 다시 읽어 요청값과 비교한다.
- 검증 후 승인요청을 실행하고 기안문서상신 창 출현을 기다린다. 이 단계는 임시저장을 동반할 수 있다.
- 개인결재선 창에서 저장된 결재선 이름을 찾고 구성원이 로드된 것을 확인한 후 지정한다.
- 결재자가 적용됐는지 확인한 뒤 기본값은 상신 직전에 멈춘다. autoSubmit이 활성화된 경우에만 최종 상신과 확인창 처리까지 수행한다. 사용자 설치본의 실제 활성화 여부는 조회하지 않았다.
- 실패 단계와 최근 실행 결과를 세션 저장소 및 나이스 화면 안내로 남긴다.

## pen도우미 1.2.35와의 차이

| 영역 | 현재 pen도우미 | 필요한 개선 |
| --- | --- | --- |
| 탭 선택 | 활성 탭 또는 도킹 대상 중심 | 로그인 완료된 나이스 탭 탐색·재사용 |
| 복무 시작 | 사용자가 신청 화면을 열어야 함 | 종류별 메뉴 이동 → 신청 창 준비 대기 |
| 값 입력 | HTML 라벨 힌트 기반 | eXbuilder 컨트롤별 입력과 계산값 검증 |
| 결재 진행 | 열린 신청/상신 창에서 한 단계 실행 | 입력 검증 후 승인요청 → 결재선 지정 연결 |
| 루틴 구조 | 종류 이름·시간 문자열·사유 중심 | 종류 코드, 시작/종료 시각, 연가 사유, 연락처, 개인결재선 등 |
| 결과 | 팝업 상태 문구 중심 | 팝업이 닫혀도 최근 단계·결과 확인 |

결론: 주소만 pen.neis.go.kr/jsp/main.jsp로 바꾸거나 신청 버튼을 추가하는 것으로는 쌤패스와 같은 흐름이 되지 않는다. 나이스 전용 실행 모듈과 종류별 입력 검증이 필요하다. 현재 기능을 해당 수준으로 구현 완료했다고 볼 수 없다.

적용 순서: 로그인된 탭 탐색 → 메뉴/신청 화면 탐색 → 종류별 필수 입력/검증 → 승인요청/결재선 지정 → 단계 로그. 각 단계는 실제 부산 나이스 화면에서 검증한 뒤 연결해야 한다.
