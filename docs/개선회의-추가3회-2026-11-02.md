# 개선회의 추가 3회

2026-11-02 · 코드 검토에 기반한 순차 검토. 외부 참석자나 별도 에이전트 회의는 아님.
결과 버전: 1.2.33. 실제 업무 사이트에 입력하거나 상신하지 않음.

## 1회차 — 복무·출장 입력 정확성

발견: 입력 함수가 수정 불가 칸을 제외하지 않고, 브라우저나 입력 이벤트가 값을 거부해도 성공으로 집계했다. 힌트가 겹치면 같은 입력칸을 두 번 사용할 수 있었고 선택지의 부분 일치가 여러 개여도 첫 항목을 골랐다.

결정 및 반영:
- disabled/readOnly 입력칸 제외.
- 이벤트 처리 직후 실제 값과 요청값을 비교하여 성공 집계.
- 한 번 채운 칸은 같은 실행에서 재사용하지 않음.
- 선택지는 정확히 일치하는 단일 항목 우선. 부분 일치도 단일 항목일 때만 선택.
- 일반 복무·출장 힌트 입력에서 체크박스·라디오·비밀번호 등 제외.

한계: 이벤트 이후 비동기 서버 검증까지 보장하지 않는다. 텍스트 칸의 모호한 힌트 매칭과 여러 프레임 응답 처리는 후속 과제다. 잘못된 선택을 피하려고 이전보다 일부 항목을 건너뛸 수 있다.

## 2회차 — 할 일·일정의 동작 일치

발견: 별도 일정 카드에 할 일 전용 완료·삭제 버튼이 표시되어 눌러도 일정에 반영되지 않았다. 연결 일정이 있는 할 일을 삭제하면 일정이 남지만 이를 설명하지 않았다.

결정 및 반영:
- 할 일 카드에만 완료·할 일 삭제 표시.
- 별도 일정에 일정 표기 추가.
- 연결된 일정이 있는 할 일 삭제 후 일정 및 구글 캘린더 일정 유지 안내.
- 완료·삭제 요청 중 중복 클릭 방지 및 실패 표시.

후속 과제: 일정 전용 수정·삭제와 할 일 삭제 되돌리기. 구글 캘린더의 실제 일정은 현재 로컬 삭제와 연동되지 않는다.

## 3회차 — 회귀 검증과 출시 범위

실행 및 통과:
- check-input.mjs: 수정 불가 필드, 값 반영 거부, 선택지 모호성, 같은 칸 중복 사용, 체크박스 제외, 정상 다중 필드 입력.
- check-settings.mjs: 설정 검증, 복무 성공/0건/오류/연결 실패, 날짜 변경, 윤년, 잘못된 날짜와 종료일 역전, 원본 루틴 보존.
- JavaScript 17개 파일 구문 검사.

검증 범위: 가짜 DOM/브라우저 응답으로 실행하는 로컬 회귀 테스트 및 구문 검사. 실제 나이스 화면이나 설치된 확장의 UI 검증을 대체하지 않는다.

다음 우선순위: 실제 복무 화면에서 항목별 매칭 확인 → 일부 입력 결과의 상세 표시 → 일정 전용 편집 및 삭제 되돌리기.

적용 방법: 확장 관리에서 pen도우미 다시 로드, 업무 탭 새로고침. content script 수정이므로 업무 탭 새로고침도 필요하다.
